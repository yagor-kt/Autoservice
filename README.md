# Автосервис

> **ИИ-проект:** приложение создано с помощью искусственного интеллекта. Код и функциональность требуют проверки перед использованием в реальных условиях.

Офлайн-приложение для механика автосервиса. Позволяет вести заявки на ремонт, добавлять работы и запчасти, отслеживать статусы, сохранять напоминания о ТО и просматривать аналитику.

## Возможности

- Авторизация по заданным в коде логину и паролю.
- Просмотр заявок с фильтрацией по статусу.
- Создание заявок и сохранение данных автомобиля и владельца.
- Просмотр деталей заявки и последовательное изменение её статуса.
- Добавление работ и запчастей из встроенных справочников.
- Подсчёт общей стоимости заявки.
- История закрытых заявок с поиском по госномеру и итоговой суммой.
- Напоминания о техническом обслуживании с указанием оставшегося времени.
- Аналитика по заявкам, выручке, среднему чеку, популярным работам и маркам автомобилей.
- Локальное хранение данных в Room. Для работы приложения интернет не требуется.

## Технологии

- Kotlin
- Jetpack Compose и Material 3
- MVVM
- Navigation Compose
- Room
- Kotlin Coroutines, Flow и StateFlow
- KSP для обработки аннотаций Room

## Требования

- Android Studio с поддержкой Android Gradle Plugin 8.10.1
- JDK 17
- Android SDK: compile/target 35
- Минимальная версия Android: API 26

## Запуск

1. Склонируйте репозиторий и откройте проект в Android Studio.
2. Дождитесь синхронизации Gradle.
3. Запустите конфигурацию приложения на эмуляторе или Android-устройстве.

На первом запуске база данных заполняется демонстрационными автомобилями, заявками, позициями и напоминаниями. Чтобы снова увидеть исходные демонстрационные данные, очистите данные приложения или переустановите его.

## Вход

- **Логин:** `admin`
- **Пароль:** `1234`

Учётные данные заданы непосредственно в коде. Это демонстрационный вариант авторизации, не предназначенный для защиты реальных данных.

## Структура проекта

```text
app/src/main/
├── java/com/example/autoservice/
│   ├── data/
│   │   ├── catalog/       # Справочники работ и запчастей
│   │   ├── dao/           # DAO Room
│   │   ├── repository/    # Репозитории
│   │   └── ...            # Сущности и AppDatabase
│   ├── ui/
│   │   ├── components/    # Общие Compose-компоненты
│   │   ├── navigation/    # Маршруты и навигация
│   │   ├── screens/       # Экраны и ViewModel
│   │   └── theme/         # Тёмная тема
│   ├── util/              # Даты, суммы, статусы и цвета
│   └── MainActivity.kt
└── res/values/
    └── strings.xml        # Статичные строки интерфейса
````


В проекте используются пакеты `data`, `ui`, `ui.theme` и `util`. Названия автомобилей, заявок и позиций, добавленные в базу, не являются строками интерфейса и хранятся в данных приложения.

## Статусы заявки

```
ACCEPTED → DIAGNOSTICS → APPROVAL → REPAIR → READY → CLOSED
```

Заявку также можно закрыть отдельной кнопкой на экране деталей. Для неё сохраняется дата закрытия.

## Ограничения

- Приложение работает локально на устройстве; синхронизации между устройствами нет.
- Авторизация демонстрационная: логин и пароль зашиты в коде.
- Кнопка «Печать чека» показывает заглушку и не выполняет оплату или печать.
- Справочники работ и запчастей задаются в коде приложения.
- Приложение предназначено для демонстрации и учебного использования. Перед практическим применением проверьте сборку, расчёты и обработку ошибок на целевых устройствах.

## Проверки

## Для ручной проверки основных сценариев проверьте:

1.Вход с корректными и некорректными данными.
2.Создание заявки и фильтрацию списка по статусу.
3.Переходы между статусами и закрытие заявки.
4.Добавление работ и запчастей, подсчёт общей стоимости.
5.Отображение суммы в истории закрытых заявок.
6.Создание и удаление напоминаний о ТО.
7.Расчёт аналитики на закрытых заявках.
8.Сохранение данных после перезапуска приложения и работу без сети.
